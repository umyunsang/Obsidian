## 1. 확정된 방침

사용자가 명시적으로 정한 사항이다. 임의로 바꾸지 않는다.

| 방침 | 내용 |
| --- | --- |
| **기존 문서 무시** | 기존 정리문서는 참고하지 않는다. 근거는 **원본 PDF뿐** |
| **템플릿 금지** | 자료마다 중요도와 구성이 다르므로, **매번 그 자료에 맞는 구조를 새로 기획**한다. 결과적으로 모든 문서가 서로 다른 구조를 갖는다 |
| **인터렉티브 시각자료** | `html preview`(JS)·SVG·Mermaid·원본 슬라이드 크롭을 적극 활용 |
| **분량** | 적지 않게. 기준선은 노트당 **20~40KB**, 인터렉티브 2~4개 |
| **페이스** | 하루 **10개** — 더 하지 않는다 |

## 2. 작업 절차

### 2.1 대상 선정

아래 §4 진행 표에서 **위에서부터 미완료 과목**을 고른다. 한 과목을 끝내고 다음으로 넘어가되, 10개를 채우면 과목 중간이라도 멈춘다.

### 2.2 근거 자료 확보

추출 번들은 `.ok/local/pdf-extract/<도메인>__<과목>__<slug>/` 에 만들어진다 — `text.md`(페이지별 텍스트) + `pages/pNNN.png`(렌더) + `meta.json`.

이 디렉터리는 **gitignore되어 있으므로 클라우드 환경에는 없다.** 다룰 과목의 PDF만 그때그때 추출한다.

```bash
# poppler-utils 필요 (pdftotext, pdftoppm, pdfinfo)
python3 scripts/pdf_lecture_extract.py \
  "ComputerScience/<도메인>/<과목>/sources/"*.pdf
```

### 2.3 원본 읽기 — 순서가 중요하다

1. `meta.json` 의 `page_chars` 로 **텍스트가 0자인 페이지**를 찾는다
2. `text.md` 전체를 읽어 강의 흐름을 파악한다
3. **0자 페이지와 핵심 도표 페이지의 이미지를 직접 본다**

> [!warning] 0자 페이지가 알맹이다
> 이 강의자료들은 페이지당 40~200자로 텍스트가 빈약하고, **텍스트가 전혀 없는 페이지는 교수의 손글씨 필기인 경우가 많다**. 02장은 32쪽 중 네 쪽이 필기였고, 그 안에 빅오 증명·표기법 상호관계·$\log(n!)$ 증명이 들어 있었다. 슬라이드 텍스트만 읽으면 강의의 절반을 놓친다.

### 2.4 구조 기획

자료를 다 읽은 뒤 **이 강의가 실제로 하려는 말**을 한 문장으로 잡고, 그것을 문서의 척추로 삼는다. 앞서 작업한 10개의 척추가 모두 달랐다.

- 01장 — gcd(60,28)을 구하는 세 가지 길
- 02장 — 무게 중심이 슬라이드가 아니라 필기에 있다
- 04장 — 세 가지 축소 형태가 복잡도를 가른다
- 08장 — 탐욕은 기법이 아니라 재판이다

이런 식으로 **자료가 가진 고유한 긴장을 찾아** 구성을 짠다. 절 번호를 그대로 나열하는 방식은 쓰지 않는다.

### 2.5 집필

- MCP `write` 로 작성한다. 한 번에 5~8KB씩 `position: append` 로 나누어 보낸다
- **한글은 유니코드 이스케이프로 보내는 편이 안전하다** — 단, `루`를 `\ub8¬`로 쓰는 식의 불완전 이스케이프가 가끔 발생하므로 거부되면 해당 글자를 의심한다
- 인용할 슬라이드는 `<과목>/assets/chNN-pNN-설명.png` 로 복사하고 `../assets/` 상대경로로 참조한다
- **인터렉티브는 원본의 수치를 그대로 쓴다.** 쓰기 전에 파이썬으로 계산해 원본 표와 대조한다
- 색상은 반드시 테마 토큰(`var(--chart-1)`, `var(--foreground)` 등)을 쓴다. 하드코딩 금지

### 2.6 검증과 마무리

```text
1. lint({ document, fix: true })          — 노트마다
2. audit({ path: "<과목>/notes" })        — 과목을 끝냈을 때
3. 미인용 이미지 정리                     — 과목을 끝냈을 때
4. 진행 표 갱신 후 커밋
```

미인용 이미지 정리는 이렇게 한다.

```bash
cd "ComputerScience/<도메인>/<과목>"
grep -oh '\.\./assets/[^)]*' notes/*.md | sed 's|../assets/||' | sort -u > /tmp/cited.txt
(cd assets && ls > /tmp/all.txt)
comm -13 /tmp/cited.txt /tmp/all.txt | tr '\n' '\0' | xargs -0 -r rm -f
```

> [!caution] macOS 파일명 주의
> 한글 파일명이 NFD로 저장되어 있어 **문자열로 직접 경로를 쓰면 찾지 못한다**. 반드시 글로브로 접근한다 — `D=$(ls -d *과목__02* | head -1)`. 공백 든 파일명은 `-print0 | xargs -0` 로 다룬다.

##### 01/python-programming — 4노트 (128KB)

발견한 **원본 오류 9건**:

- `문제풀이_1_10` 4쪽 — 문제 4 입출력 예 셋째 줄이 `x=4, n=2`에 대해 `[-4, -8]`. 실제로는 `[4, 8]`이며, 입력에서 음수 부호가 빠졌다
- 같은 자료 5쪽 — 문제 5(콜라츠)의 입력 **626331이 제한 조건 `1 이상 10000 이하`를 위반**한다. 게다가 "500번을 시도해도 1이 되지 못한다"고 적었으나 실제로는 **508단계 만에 1이 된다**(직접 계산). 콜라츠 추측의 반례처럼 읽히지만 인위적 상한에 여덟 단계 차이로 걸린 것뿐이다
- 같은 자료 2·4·5쪽 — 입출력 예 표의 열 머리가 `arr`인데 매개변수는 스칼라 `x`다(배열 문제의 서식 복사)
- 같은 자료 8쪽 — 한 쪽 안에서 매개변수를 `array`와 `arr` 두 이름으로 번갈아 부른다
- `23-2 중간고사` 4번 — 무한 급수에 **종료 조건이 없다**. 참고로 이 급수는 니라칸타 급수이며 $\pi$로 수렴한다(원본은 이름도 수렴값도 적지 않았다)
- 같은 시험지 5번 — 범위는 `1부터 99까지`인데 `2자리의 정수`라 적었다. 1~9는 한 자리다

##### 02/discrete-mathematics — 6노트 (부분, 191KB)

이 과목 자료의 성격이 앞 과목들과 또 달랐다. **한 파일 안에 두 계열의 슬라이드가 블록으로 번갈아 붙어 있다** — 로젠 8판을 옮긴 영어 슬라이드는 개념을 *의미*로 가르치고(자연어 번역, 시스템 명세, 예문), 한국어 교재 슬라이드는 `[표 2-1]`·`[정의 2-3]`·`[예제 2-14]` 같은 번호 붙은 도표로 *계산*을 가르친다(진리표, 연산자 우선순위표, 스택 파싱). 두 계열이 같은 개념을 다른 이름·다른 기호로 부르고, **같은 규칙을 두 번 적으면서 한쪽이 틀린 자리**도 있다. 그 어긋남을 각 노트의 척추로 삼았다.

| 새 노트 | 묶은 원본 | 척추 |
| --- | --- | --- |
| 01 | 1 이산수학 소개(24쪽) | 첫 시간이 정의 대신 같은 제목의 사진 두 장(맥주·물방울)을 준다 — 이산은 대상의 성질이 아니라 기록 방식이다. 그런데 9쪽 분류표가 그 태도를 배반한다 |
| 02 | 수학적 모델과 논리 1~35쪽 | 24~31쪽 여덟 장은 논리학이 아니라 컴파일러다 — 두 스택으로 괄호를 표 하나로 대체한다 |
| 03 | 같은 자료 36~59쪽 | 이 블록의 규칙은 전부 대체 규칙이다. 후건 부정이 네 번 적히고 52쪽 하나만 틀렸다 |
| 04 | 같은 자료 60~91쪽 | 2.3절 이름이 약속한 「증명↔검증」의 다리가 없다. 증명은 모든 경우를 덮고 테스트는 고른 경우만 덮으며, 67쪽이 그 실물 예다 |
| 05 | 집합 및 집합연산 1~27쪽 | 순서·중복을 버렸기에 남는 질문은 「몇 개인가」뿐 — 그런데 네 칸 중 하나는 채울 수 없다. 21~23쪽이 튜플로 순서를 되사 와 관계를 정의한다 |
| 06 | 같은 자료 28~46쪽 | 두 집합이 같음을 **진리표로** 증명할 수 있다는 사실 자체가 결론이다 — 집합의 대수는 논리의 대수다 |

발견한 **원본 오류·불일치 16건**(그중 셋은 계산으로 반례까지 확인):

- `수학적 모델과 논리` **52쪽** — 후건 부정(Modus Tollens)의 기호식이 `p→q, ￢p ∴ ￢q`로 적혀 있다. **「전건 부정의 오류」라는 이름이 따로 있는 잘못된 추론**이며 $P=$거짓·$Q=$참에서 반례가 나온다(진리표로 확인). 49쪽 `[표 2-9]`와 59쪽 인용, 그리고 **같은 슬라이드의 영어 예문은 모두 정확하다**
- 같은 자료 **51쪽** — Modus Ponens의 대응 항진 명제를 `(q ∧ (p→q)) → q`로 적었다. 첫 항이 `p`여야 한다(공허하게 참일 뿐 전건 긍정과 무관)
- 같은 자료 **67쪽** — 배리법 예제의 「$r+1$은 소수이다」가 성립하지 않는다. $q$가 2·3·5·7·11까지는 우연히 맞다가 **$q=13$에서 $30031 = 59 \times 509$로 깨진다**. 「$r+1$의 소인수는 모두 $q$보다 크다」로 고치면 복구된다
