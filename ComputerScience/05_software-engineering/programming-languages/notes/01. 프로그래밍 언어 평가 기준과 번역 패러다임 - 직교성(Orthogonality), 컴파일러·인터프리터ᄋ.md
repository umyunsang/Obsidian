> [!abstract] 핵심 요약
> 프로그래밍 언어는 **가독성**, **작성력**, **신뢰성**, **비용**이라는 상충되는 목표 간의 엔지니어링 절충(Trade-off)을 통해 발전해 왔다.
> 특히 소수의 기본 구조가 임의로 결합될 수 있어 예외가 적은 성질을 뜻하는 **직교성(Orthogonality)**은 언어의 학습 용이성을 높이지만, 지나치면 복잡성을 초래한다. 현대 실행 엔진은 정적 컴파일의 속도와 동적 인터프리터의 이식성을 결합한 **JIT(Just-In-Time) 하이브리드 컴파일** 모델을 표준으로 채택한다.

## 1. 컴파일 vs 인터프리터 vs JIT 하이브리드 파이프라인

```mermaid
flowchart TD
    subgraph COMPILER["1. 순수 컴파일러 (C, C++, Rust, Go)"]
        SRC1["소스 코드 (.c)"] --> COMP["컴파일러 (어휘·구문·코드생성)"]
        COMP --> OBJ["네이티브 기계어 (.exe)"]
        OBJ --> CPU1["CPU 즉각 고속 실행"]
    end

    subgraph HYBRID["2. JIT 하이브리드 VM (Java, C#, V8 JS)"]
        SRC2["소스 코드 (.java)"] --> JCOMP["javac 컴파일러"]
        JCOMP --> BYTE["플랫폼 독립 바이트코드 (.class)"]
        BYTE --> VM["JVM / V8 인터프리터"]
        VM -->|"핫스팟(Hotspot) 프로파일링"| JIT["JIT 컴파일러 (런타임 기계어 캐싱)"]
        JIT --> CPU2["CPU 네이티브 실행"]
    end
```

## 2. 언어 평가 4대 기준과 세부 평가 요소

| 평가 기준 | 핵심 세부 요인 | 언어 간 대표 비교 |
| :-- | :-- | :-- |
| **가독성 (Readability)** | 단순성(Simplicity), 직교성(Orthogonality), 제어문/자료형 표현력 | Python(높은 가독성) vs APL/Perl(극단적 축약) |
| **작성력 (Writability)** | 간결성(Conciseness), 추상화 지원(데이터/프로세스), 표현력 | 현대 고수준 언어 vs 어셈블리 |
| **신뢰성 (Reliability)** | 엄격한 타입 검사(Type Checking), 예외 처리(Exception Handling), 앨리어싱(Aliasing) 제한 | Rust/Java(메모리·타입 안전) vs C(포인터 자유도) |
| **비용 (Cost)** | 프로그래머 훈련 비용, 컴파일/실행 시간, 신뢰성 결여로 인한 버그 수정 비용 | TCO(총소유비용) 관점에서 신뢰성과 유지보수성이 최우선 |
