* [01. 현대 소프트웨어 딜리버리와 DORA 지표 - 배포 빈도, 리드 타임, 변경 실패율과 복구 시간(MTTR)](./01.%20%ED%98%84%EB%8C%80%20%EC%86%8C%ED%94%84%ED%8A%B8%EC%9B%A8%EC%96%B4%20%EB%94%9C%EB%A6%AC%EB%B2%84%EB%A6%AC%EC%99%80%20DORA%20%EC%A7%80%ED%91%9C%20-%20%EB%B0%B0%ED%8F%AC%20%EB%B9%88%EB%8F%84%2C%20%EB%A6%AC%EB%93%9C%20%ED%83%80%EC%9E%84%2C%20%EB%B3%80%EA%B2%BD%20%EC%8B%A4%ED%8C%A8%EC%9C%A8%EA%B3%BC%20%EB%B3%B5%EA%B5%AC%20%EC%8B%9C%EA%B0%84%28MTTR%29.md) - 고성능 엔지니어링 조직의 소프트웨어 딜리버리 및 운영 성과를 측정하는 DevOps Research and Assessment(DORA) 4대 핵심 지표(1. 배포 빈도 Deployment Frequency, 2. 변경 리드 타임 Lead Time for Changes, 3. 변경 실패율 Change Failure Rate, 4. 서비스 복구 시간 Time to Restore Service / MTTR), 밸류 스트림 맵핑(Value Stream Mapping)을 통한 개발 낭비 식별, 그리고 엔지니어링 처리량(Throughput)과 안정성(Stability)의 동시 극대화 전략을 인터랙티브 DORA 성숙도 진단기로 학습한다.
* [02. GitHub Actions 기반 CI·CD 파이프라인 - 자동 빌드, 매트릭스 테스팅, 시크릿 관리와 릴리스 자동화](./02.%20GitHub%20Actions%20%EA%B8%B0%EB%B0%98%20CI%C2%B7CD%20%ED%8C%8C%EC%9D%B4%ED%94%84%EB%9D%BC%EC%9D%B8%20-%20%EC%9E%90%EB%8F%99%20%EB%B9%8C%EB%93%9C%2C%20%EB%A7%A4%ED%8A%B8%EB%A6%AD%EC%8A%A4%20%ED%85%8C%EC%8A%A4%ED%8C%85%2C%20%EC%8B%9C%ED%81%AC%EB%A6%BF%20%EA%B4%80%EB%A6%AC%EC%99%80%20%EB%A6%B4%EB%A6%AC%EC%8A%A4%20%EC%9E%90%EB%8F%99%ED%99%94.md) - 현대 클라우드 네이티브 CI/CD 자동화 플랫폼 GitHub Actions의 코어 아키텍처(Workflows, Events: push/pull_request/schedule, Jobs, Runners: GitHub-hosted vs Self-hosted, Steps, Actions), YAML 파이프라인 선언 문법, 매트릭스 빌드(Matrix Build - 다중 OS 및 런타임 버전 병렬 테스트), Repository Secrets 암호화 및 OIDC 기반 AWS/GCP 클라우드 무자격증명(Keyless) 인증, 그리고 빌드 아티팩트 캐싱(actions/cache)을 인터랙티브 CI/CD 파이프라인 트리거 계산기로 학습한다.
* [03. 트렁크 기반 개발(TBD)과 피처 플래그 - GitFlow 한계 극복, 단기 브랜치와 점진적 릴리스 제어](./03.%20%E1%84%90%E1%85%B3%E1%84%85%E1%85%A5%E1%86%BC%E1%84%8F%E1%85%B3%20%E1%84%80%E1%85%B5%E1%84%87%E1%85%A1%E1%86%AB%20%E1%84%80%E1%85%A2%E1%84%87%E1%85%A1%E1%86%AF%28TBD%29%E1%84%80%E1%85%AA%20%E1%84%91%E1%85%B5%E1%84%8E%E1%85%A5%20%E1%84%91%E1%85%B3%E1%86%AF%E1%84%85%E1%85%A2%E1%84%80%E1%85%B3%20-%20GitFlow%20%E1%84%92%E1%85%A1%E1%86%AB%E1%84%80%E1%85%A8%20%E1%84%80%E1%85%B3%E1%86%A8%E1%84%87%E1%85%A9%E1%86%A8%2C%20%E1%84%83%E1%85%A1%E1%86%AB%E1%84%80%E1%85%B5%20%E1%84%87%E1%85%B3%E1%84%85%E1%85%A2%E1%86%AB%E1%84%8E%E1%85%B5%E1%84%8B%E1%85%AA%20%E1%84%8C%E1%85%A5%E1%86%B7%E1%84%8C%E1%85%B5%E1%86%AB%E1%84%8C%E1%85%A5%E1%86%A8%20%E1%84%85%E1%85%B5%E1%86%AF%E1%84%85%E1%85%B5%E1%84%89%E1%85%B3%20%E1%84%8C%E1%85%A6.md) - 장기 브랜치(Long-lived Branches) 기반 GitFlow의 머지 헬(Merge Hell) 및 릴리스 지연 한계, 트렁크 기반 개발(Trunk-Based Development: TBD)의 핵심 철학(모든 엔지니어가 단일 main 트렁크에 매일 1~2회 이상 빈번하게 병합), 미완성 기능의 프로덕션 안전 배포를 가능하게 하는 피처 플래그(Feature Flags / Feature Toggles), 런타임 동적 토글링, 카나리(Canary) 릴리스 및 다크 론칭(Dark Launching)을 인터랙티브 TBD 브랜치 및 피처 토글 시뮬레이터로 학습한다.
* [04. 쉬프트 레프트(Shift-Left) 테스팅과 품질 공학 - 테스트 피라미드, 정적 분석(SAST)과 카나리 배포](./04.%20%EC%89%AC%ED%94%84%ED%8A%B8%20%EB%A0%88%ED%94%84%ED%8A%B8%28Shift-Left%29%20%ED%85%8C%EC%8A%A4%ED%8C%85%EA%B3%BC%20%ED%92%88%EC%A7%88%20%EA%B3%B5%ED%95%99%20-%20%ED%85%8C%EC%8A%A4%ED%8A%B8%20%ED%94%BC%EB%9D%BC%EB%AF%B8%EB%93%9C%2C%20%EC%A0%95%EC%A0%81%20%EB%B6%84%EC%84%9D%28SAST%29%EA%B3%BC%20%EC%B9%B4%EB%82%98%EB%A6%AC%20%EB%B0%B0%ED%8F%AC.md) - 소프트웨어 결함 발견 시점을 개발 초기 단계로 앞당기는 쉬프트 레프트(Shift-Left) 품질 전략, 마이크 콘(Mike Cohn)의 테스트 피라미드(Test Pyramid: 단위 테스트 Unit -> 통합 테스트 Integration -> 엔드투엔드 E2E 테스트), 테스트 비용과 실행 속도 트레이드오프, 정적 애플리케이션 보안 테스팅(SAST)과 의존성 취약점 스캔(Dependabot, Snyk), 그리고 무중단 배포 전략(블루-그린 Blue-Green vs 카나리 Canary 릴리스)을 인터랙티브 테스트 피라미드 비용 계산기로 학습한다.
* [05. 린 소프트웨어 엔지니어링과 이너소스 - MVP 가설 검증, 밸류 스트림 매핑(VSM)과 오픈소스 협업 모델](./05.%20%E1%84%85%E1%85%B5%E1%86%AB%20%E1%84%89%E1%85%A9%E1%84%91%E1%85%B3%E1%84%90%E1%85%B3%E1%84%8B%E1%85%B0%E1%84%8B%E1%85%A5%20%E1%84%8B%E1%85%A6%E1%86%AB%E1%84%8C%E1%85%B5%E1%84%82%E1%85%B5%E1%84%8B%E1%85%A5%E1%84%85%E1%85%B5%E1%86%BC%E1%84%80%E1%85%AA%20%E1%84%8B%E1%85%B5%E1%84%82%E1%85%A5%E1%84%89%E1%85%A9%E1%84%89%E1%85%B3%20-%20MVP%20%E1%84%80%E1%85%A1%E1%84%89%E1%85%A5%E1%86%AF%20%E1%84%80%E1%85%A5%E1%86%B7%E1%84%8C%E1%85%B3%E1%86%BC%2C%20%E1%84%87%E1%85%A2%E1%86%AF%E1%84%85%E1%85%B2%20%E1%84%89%E1%85%B3%E1%84%90%E1%85%B3%E1%84%85%E1%85%B5%E1%86%B7%20%E1%84%86%E1%85%A2%E1%84%91%E1%85%B5%E1%86%BC%28VSM%29%E1%84%80%E1%85%AA%20%E1%84%8B%E1%85%A9%E1%84%91%E1%85%B3%E1%86%AB%E1%84%89%E1%85%A9%E1%84%89%E1%85%B3%20%E1%84%92.md) - 에릭 리스(Eric Ries)의 린 스타트업(Lean Startup) 철학과 소프트웨어 엔지니어링의 융합, 최소 기능 제품(MVP, Minimum Viable Product) 정의, 만들기-측정-학습(Build-Measure-Learn) 피드백 루프, 가치 흐름에서 비부가가치 대기 시간을 제거하는 밸류 스트림 맵핑(VSM, Value Stream Mapping), 엔지니어링 리드 타임 효율(Flow Efficiency), 그리고 기업 내부에서 오픈소스 개발 문화를 도입하는 이너소스(InnerSource) 거버넌스를 인터랙티브 VSM 흐름 효율성 계산기로 학습한다.
