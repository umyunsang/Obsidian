## 1. 왜 벡터화(Vectorization)인가

텍스트를 자동으로 분류하려면 먼저 텍스트 데이터를 컴퓨터가 다룰 수 있는 형태로 바꾸어야 하고, 그 대표적인 방법이 문서를 **벡터화**하는 것이다 (p.3).

```mermaid
graph LR
  A["원문 텍스트 (문자열)"] --> B["BoW (등장 여부/횟수)"]
  B --> C["TF-IDF (빈도 + 희소성 가중치)"]
  C --> D["Word2Vec / BERT (의미 임베딩)"]
  B -.->|이번 챕터| C
```

## 2. BoW(Bag of Words, 단어가방 모델)

### 2.1 정의

자연어처리에서의 단어가방 모델은 (p.4):

- 텍스트 데이터를 수치화하는 가장 기초적인 방법 중 하나
- 문서를 =="단어들의 집합(가방)"== 으로 간주
- 즉, **단어의 순서는 무시**하고 등장 여부(binary BoW) 혹은 횟수(count BoW)만 고려

> [!IMPORTANT]
> "가방(bag)"이라는 이름이 핵심이다. 가방에 단어를 쏟아 넣으면 **어떤 단어가 몇 개 들어 있는지는 알 수 있지만, 원래 어떤 순서로 있었는지는 알 수 없다.** 이것이 BoW의 정체성이자 동시에 최대 한계다.

### 2.2 처리 절차 2단계

1. **단어사전(vocabulary) 생성** — 모든 문서에 등장하는 단어를 모아 사전 구축 (실제로는 토큰화한다)
2. **문서 → 벡터 변환** — 각 문서를 이 단어 집합 기준으로 숫자 벡터로 변환

강의 예시 (p.4) — 문서1 `"나는 오늘 학교에 갔다"`, 문서2 `"오늘 나는 도서관에 갔다"`

- 단어사전 `['갔다', '나는', '도서관에', '오늘', '학교에']`
- 문서1 `[1, 1, 0, 1, 1]` · 문서2 `[1, 1, 1, 1, 0]`

> [!TIP]
> **단어사전은 순서가 중요하다.** 사전의 $i$번째 단어가 벡터의 $i$번째 차원에 대응하므로, 사전 순서가 바뀌면 같은 문서라도 전혀 다른 벡터가 된다. 그래서 보통 **정렬(sorted)** 해서 고정한다.

### 2.3 장단점 (p.5)

- **장점** — 단순하고 구현이 쉬움. 작은 데이터셋에서는 꽤 효과적
- **단점 ①** — 단어의 순서·문맥·의미가 모두 사라짐
- **단점 ②** — 단어 수가 많아지면 벡터 차원이 매우 커짐 (**차원의 저주**)
- **단점 ③** — 등장하지 않은 단어는 0이므로 **희소 행렬(sparse matrix)** 이 됨

정리하자면 BoW는 "텍스트를 수학적으로 다루기 위한 **출발점**" 같은 개념이며, 확장 방향은 (1) TF-IDF — 단순 빈도 대신 문서 전체에서 중요한 단어에 더 높은 가중치, (2) Word2Vec·BERT — 단어 의미까지 반영한 벡터다 (p.5).

### 3.1 1단계 — 단어사전 만들기

세 문서의 단어를 모두 모아 (대소문자 무시, 정렬해서) 사전을 만든다.

```text
인덱스   0    1     2     3     4      5        6
단어    A    am    are   boy   I      pretty   you
```

단어는 **7종류**이므로 각 문서는 **7차원 벡터**로 표현된다.

### 3.2 2단계 — 벡터 변환 (정답)

- **문서1** `I am a boy` — binary `[1,1,0,1,1,0,0]` · count `[1,1,0,1,1,0,0]`
- **문서2** `I am pretty, pretty` — binary `[0,1,0,0,1,1,0]` · count `[0,1,0,0,1,2,0]` ← ==`pretty` 가 2로== 유일하게 갈라지는 자리
- **문서3** `you are a boy` — binary `[1,0,1,1,0,0,1]` · count `[1,0,1,1,0,0,1]`

> [!IMPORTANT]
> 문서2의 벡터 `[0,1,0,0,1,1,0]` 만 봐도 **어떤 단어가 있는지는 알 수 있다.** 하지만 원래 문서에서 단어들이 **어떤 순서로** 있었는지는 알 수 없다 — 이것이 곧 **단어가방 모델**이라는 이름의 이유다.
>
> 또 하나 — **두 방식의 차이가 드러나는 곳은 문서2뿐이다.** 문서1·문서3은 중복 단어가 없어 binary와 count가 완전히 동일하다. 즉 중복 단어가 없으면 두 표현은 구분되지 않는다.

## 4. TF-IDF — 흔한 단어의 점수를 깎는다

### 4.1 개념 (p.6)

- **TF** (Term Frequency, 단어 빈도) — 문서 안에서 어떤 단어가 얼마나 자주 등장하는지. 같은 문서에서 많이 나올수록 **중요도 ↑**
- **IDF** (Inverse Document Frequency, 역문서 빈도) — 모든 문서에 흔하게 등장하는 단어인지. 여러 문서에 흔할수록 **중요도 ↓**

> [!TIP]
> **발표 수업 비유** (p.6)
>
> - 어떤 학생이 같은 말을 계속 반복하면(→ 높은 TF), 그 말은 그 학생 발언에서 중요한 단어일 수 있다.
> - 하지만 그 말을 모든 학생이 다 한다면(→ 낮은 IDF), 특별히 눈에 띄지 않는다.
> - **결론**: 다른 학생들은 잘 안 하는데 특정 학생만 여러 번 강조한 말이 그 학생을 대표하는 키워드다.

#### ⭐ 시험 포인트 — TF와 IDF는 각각 무엇의 함수인가

> [!IMPORTANT]
> **"TF는 같은 단어라도 문서마다 값이 다르다" → ⭕ (참)**
>
> - **TF는 (단어, 문서) 쌍의 함수**다. 문서가 바뀌면 값도 바뀜다. 예: `학교`의 TF는 문서2(2단어)에서 $1/2 = 0.50$, 문서3(7단어)에서 $1/7 \approx 0.14$
> - **IDF는 (단어)만의 함수**다. 코퍼스 전체를 보고 한 번 계산하므로 **문서가 바뀜어도 그대로**다. `학교`의 IDF는 어느 문서에서든 0.29 하나뿐이다
>
> 따라서 최종 TF-IDF 값이 문서마다 달라지는 원인은 **전적으로 TF 쪽**에 있다. 계산기에서 `IDF` 단계를 고른 채 문서 버튼을 눌러도 막대가 꽈짝도 안 움직이는 이유다.

### 4.2 계산 예제의 공통 준비 (p.8)

강의는 다음 4개 문서($N = 4$)를 쓴다. 전처리를 아직 배우지 않았으므로 **조사만 제외**한다고 가정한다.

- **문서1** `"나는 학교에 간다"` → `나 학교 간다` (3단어)
- **문서2** `"학교에서 공부한다"` → `학교 공부한다` (2단어)
- **문서3** `"친구와 학교에서 만나서 다른 친구네 집에 갔다"` → `친구 학교 만나서 다른 친구 집 갔다` (7단어)
- **문서4** `"운동 좋아하는 친구와 함께 운동을 했다"` → `운동 좋아하는 친구 함께 운동 했다` (6단어)

정렬된 단어사전은 13개 → **13차원 벡터**가 된다.

```text
['간다', '갔다', '공부한다', '나', '다른', '만나서', '운동', '좋아하는', '집', '친구', '학교', '함께', '했다']
```

> [!NOTE]
> 단어사전 구축까지는 방법1·방법2가 **완전히 동일**하다. 갈라지는 지점은 TF 정의, IDF 수식, 그리고 정규화 유무다.

### 4.3 단계별 TF-IDF 계산기

강의 p.9~17의 모든 계산을 하나로 모은 위젯이다. **문서 → 방법 → 단계** 순서로 눌러보면 값이 어떻게 변해가는지 보인다.

```html preview
<div style="font-family:system-ui,sans-serif;padding:18px;color:var(--foreground)">
  <div id="tRow1" style="display:flex;gap:6px;flex-wrap:wrap;margin-bottom:8px"></div>
  <div id="tRow2" style="display:flex;gap:6px;flex-wrap:wrap;margin-bottom:8px"></div>
  <div id="tRow3" style="display:flex;gap:6px;flex-wrap:wrap;margin-bottom:14px"></div>

  <div id="tFormula" style="padding:10px 12px;background:var(--card);border:1px solid var(--border);
    border-radius:var(--radius);font-size:13px;margin-bottom:14px;line-height:1.6"></div>

  <div id="tBars" style="display:flex;flex-direction:column;gap:4px"></div>
  <div id="tVec" style="margin-top:14px;font-size:12px;color:var(--muted-foreground);
    word-break:break-all;line-height:1.7"></div>

  <script>
    var VOCAB = ['간다','갔다','공부한다','나','다른','만나서','운동','좋아하는','집','친구','학교','함께','했다'];
    var DOCS = [
      { t: '나 학교 간다', w: ['나','학교','간다'] },
      { t: '학교 공부한다', w: ['학교','공부한다'] },
      { t: '친구 학교 만나서 다른 친구 집 갔다', w: ['친구','학교','만나서','다른','친구','집','갔다'] },
      { t: '운동 좋아하는 친구 함께 운동 했다', w: ['운동','좋아하는','친구','함께','운동','했다'] }
    ];
    var N = 4;
    var DF = {};
    VOCAB.forEach(function (w) {
      DF[w] = DOCS.filter(function (d) { return d.w.indexOf(w) >= 0; }).length;
    });

    var st = { doc: 0, method: 1, step: 'tf' };

    function cnt(di, w) {
      return DOCS[di].w.filter(function (x) { return x === w; }).length;
    }
    function tf(di, w) {
      return st.method === 1 ? cnt(di, w) / DOCS[di].w.length : cnt(di, w);
    }
    function idf(w) {
      return st.method === 1 ? Math.log(N / DF[w]) : Math.log((N + 1) / (DF[w] + 1)) + 1;
    }
    function prodVec(di) {
      return VOCAB.map(function (w) { return tf(di, w) * idf(w); });
    }
    function normVec(di) {
      var p = prodVec(di);
      var n = Math.sqrt(p.reduce(function (a, b) { return a + b * b; }, 0));
      return p.map(function (v) { return n ? v / n : 0; });
    }
    function fmt(v) {
      if (st.method === 2 && st.step === 'tf') return String(v);
      return st.method === 1 ? v.toFixed(2) : v.toFixed(4);
    }

    }

    function steps() {

        : [['tf', 'TF'], ['idf', 'IDF'], ['prod', 'TF×IDF'], ['norm', 'L2 정규화 (최종)']];
    }
```

> **위젯으로 확인해볼 것 세 가지**
>
> 1. `IDF` 단계에서 방법1↔방법2를 번갈아 누르면, 방법1은 `학교`가 0.29까지 바닥으로 까지는 반면 방법2는 1.22로 완만하게 깎인다. 스무딩 `+1`의 효과다.
> 2. 방법1 `TF` 단계에서 문서2(2단어)와 문서3(7단어)을 번갈아 보면 `학교` 값이 0.50 ↔ 0.14로 크게 바뀐다. 문서 길이가 TF에 직결된다는 뜻.
> 3. 방법2에서 `TF×IDF` → `L2 정규화`로 넘어가면 막대 **모양은 그대로이고 숫자만 줄어든다.** 정규화는 방향을 바꾸지 않고 길이만 맞추는 연산이기 때문이다.

### 4.4 방법1 — 문서 길이를 TF에 반영, 정규화 없음 (p.9~12)

$$
\text{TF}(t, d) = \frac{\text{문서 } d \text{ 내 단어 } t \text{ 의 빈도수}}{\text{문서 } d \text{ 의 총 단어수}}
\qquad
\text{IDF}(t) = \ln\!\left(\frac{N}{df(t)}\right)
$$

강의가 직접 풀어준 문서1 `"나 학교 간다"` (p.12):

- `나`: $0.33 \times 1.39 \approx 0.46$
- `학교`: $0.33 \times 0.29 \approx 0.10$
- `간다`: $0.33 \times 1.39 \approx 0.46$

> [!IMPORTANT]
> `나`와 `간다`는 문서1에만 나오므로 0.46, `학교`는 4문서 중 3개에 나오는 흔한 단어라 0.10으로 깎였다. 같은 문서 안에서 **TF가 똑같아도 IDF가 순위를 갈라놓는다.**

나머지 문서는 강의에서 "직접 완성해보세요"로 남겨둔 과제다. 계산기의 `방법1 → TF×IDF` 단계에서 문서2·문서3·문서4를 눌러보면 전체 벡터를 확인할 수 있다.

<details>
<summary>과제 정답 — 문서2~4의 13차원 벡터 (스포일러)</summary>

**문서2** `학교 공부한다` (2단어) — `공부한다` $0.50 \times 1.39 \approx 0.69$, `학교` $0.50 \times 0.29 \approx 0.14$

```text
[0, 0, 0.69, 0, 0, 0, 0, 0, 0, 0, 0.14, 0, 0]
```

**문서3** `친구 학교 만나서 다른 친구 집 갔다` (7단어) — `친구` $0.29 \times 0.69 \approx 0.20$, `갔다`·`다른`·`만나서`·`집` 각 $0.14 \times 1.39 \approx 0.20$, `학교` $0.14 \times 0.29 \approx 0.04$

```text
[0, 0.20, 0, 0, 0.20, 0.20, 0, 0, 0.20, 0.20, 0.04, 0, 0]
```

**문서4** `운동 좋아하는 친구 함께 운동 했다` (6단어) — `운동` $0.33 \times 1.39 \approx 0.46$, `좋아하는`·`함께`·`했다` 각 $0.17 \times 1.39 \approx 0.23$, `친구` $0.17 \times 0.69 \approx 0.12$

```text
[0, 0, 0, 0, 0, 0, 0.46, 0.23, 0, 0.12, 0, 0.23, 0.23]
```

이 값들은 강의자료에 정답이 없는 부분을 직접 계산한 것이다. 검증 방법: 동일한 계산 로직으로 **방법2**를 돌려 강의 p.17의 최종 값(0.6445 / 0.8429 / 0.6006 / 0.7244 …)과 소수점 4자리까지 전부 일치함을 확인했다.

소수점은 강의와 동일하게 **정확한 값으로 계산 후 마지막에 반올림**했다. 반올림된 값끼리 먼저 곱하면 미세하게 달라질 수 있다 (문서2의 `공부한다`: $0.50 \times 1.39 = 0.695 \to 0.70$ 이지만 정확한 값은 $0.5 \times 1.3863 = 0.6931 \to 0.69$).

</details>

> [!TIP]
> **문서3의 함정** — `친구`는 2번 나왔는데 1번만 나온 `갔다`·`집`과 점수가 **똑같은 0.20**이다. $df = 2$ 일 때 $\ln(4/2)$ 가 정확히 $\ln(4)/2$ 이므로, TF가 2배가 되어도 IDF가 정확히 절반이 되어 상쇄된다. **"많이 나오면 무조건 중요"가 아니라는 사례**다. 반면 문서4의 `운동`은 2번 나왔고 $df = 1$ 이라 감점이 없어 0.46으로 문서 내 최고가 된다.

### 4.5 방법2 — 싸이킷런 `TfidfVectorizer` 방식 (p.13~17)

$$
\text{TF}(t, d) = \text{단순 빈도수 (count BoW)}
\qquad
\text{IDF}(t) = \ln\!\left(\frac{N + 1}{df(t) + 1}\right) + 1
$$

1. **TF** — 문서 길이를 나누지 않은 raw count (p.13)
2. **IDF** — 분자·분모에 `+1`, 전체에 `+1` (p.14)
3. **TF × IDF** — 문서1은 `나` 1.9163, `학교` 1.2231, `간다` 1.9163 (p.15)
4. **L2 정규화** — 각 문서 벡터를 자기 norm으로 나눈다 (p.16~17)

$$
\|\vec{d_1}\| = \sqrt{1.9163^2 + 1.2231^2 + 1.9163^2} \approx 2.9737
$$

따라서 `나` = $1.9163 / 2.9737 \approx 0.6445$, `학교` = $1.2231 / 2.9737 \approx 0.4114$, `간다` = $0.6445$ 가 된다.

> [!TIP]
> **왜 `+1`을 붙일까?** 분모의 `+1`은 학습에 없던 단어의 $df = 0$ 으로 인한 0-나눗셈을 막고, 전체의 `+1`은 모든 문서에 등장해 $\ln$ 값이 0이 되는 단어도 완전히 소멸하지 않게 한다.

### 4.6 두 방법은 어디서 갈라지는가

- **단어사전** — 둘 다 동일하다
- **TF** — 방법1은 빈도수를 문서 총 단어수로 나누고, 방법2는 빈도수 그대로 쓴다
- **IDF** — 방법1은 $\ln(N/df)$, 방법2는 $\ln((N+1)/(df+1)) + 1$ (스무딩)
- **문서 길이 보정** — 방법1은 TF 단계에서, 방법2는 마지막 L2 정규화에서 처리한다
- **벡터 크기** — 방법1은 문서마다 제각각, 방법2는 모든 문서가 단위 길이($\text{norm} = 1$)

> [!WARNING]
> TF-IDF의 세부 수식은 **하나로 정해져 있지 않다** (p.7). 교재·라이브러리마다 로그 밑, 스무딩, 정규화 방식이 다르므로 "어떤 정의를 썼는지"를 항상 함께 밝혀야 한다.

### 4.7 싸이킷런으로 확인 (p.18)

```python
from sklearn.feature_extraction.text import TfidfVectorizer
import pandas as pd

docs = [
    "나 학교 간다",
    "학교 공부한다",
    "친구 학교 만나서 다른 친구 집 갔다",
    "운동 좋아하는 친구 함께 운동 했다"
]

# TF-IDF 벡터화
vectorizer = TfidfVectorizer(token_pattern=r"(?u)\b\w+\b")   # (1글자 이상 허용)
tfidf_matrix = vectorizer.fit_transform(docs)

# 결과를 보기 쉽게 DataFrame으로 변환
df = pd.DataFrame(
    tfidf_matrix.toarray(),
    columns=vectorizer.get_feature_names_out()
)
print(df)
```

## 5. 생각해볼 포인트 (p.12)

<details>
<summary>① 여러 문서에서 등장하면 IDF가 낮은가요?</summary>

**낮아진다.** $df$ 가 분모에 있으므로 등장 문서 수가 늘수록 $\ln(N/df)$ 는 작아진다. 위 예제에서 `학교`는 4문서 중 3개에 등장해 IDF 0.29, 1개 문서에만 있는 `간다`는 1.39다. **약 4.8배 차이**로 흔한 단어의 영향력이 체계적으로 억제된다.

계산기의 `IDF` 단계에서 막대 길이를 보면 바로 확인된다.

</details>

<details>
<summary>② 긴 문서와 짧은 문서가 TF 차이가 나나요?</summary>

**방법1에서는 난다.** TF를 문서 총 단어수로 나누므로 짧은 문서일수록 단어 하나의 TF가 커진다. 2단어 문서2에서 `학교`는 $1/2 = 0.5$, 7단어 문서3에서 `학교`는 $1/7 \approx 0.14$ 다. 같은 1회 등장인데 3배 이상 차이다.

**방법2는 TF 단계에선 차이가 없다** (둘 다 1). 대신 마지막 L2 정규화가 같은 역할을 대신해, 최종적으로 문서2의 `학교`는 0.5380, 문서3의 `학교`는 0.2431로 다시 벌어진다.

</details>

<details>
<summary>③ 같은 단어가 문서별로 TF, IDF 값이 다른가요?</summary>

- **TF는 문서마다 다르다.** TF는 (단어, 문서) 쌍의 함수기 때문이다.
- **IDF는 문서와 무관하게 단어당 하나로 고정된다.** IDF는 코퍼스 전체를 보고 계산하는 (단어)만의 함수다.

즉 최종 TF-IDF 값이 문서마다 달라지는 원인은 **전적으로 TF 쪽**에 있다. 계산기에서 `IDF` 단계를 고른 채 문서 버튼을 눌러도 값이 바뀌지 않는 이유다.

</details>
