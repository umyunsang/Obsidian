> [!abstract] 이 시험지가 실제로 하는 말
> 앞선 세 문서가 다룬 스물한 문제는 예외 없이 같은 모양이었다 — `solution` 함수가 인자를 받아 값을 `return`하고, 슬라이드에 붙은 **입출력 예**가 정답을 정한다. 코드가 맞는지는 표를 보면 안다.
>
> 23-2 중간고사 8문항에는 `return`이 하나도 없다. 전부 `input`으로 받고 `print`로 내놓는다. 그중 두 문항(3·5번)은 아예 `random`을 쓴다. **난수가 들어오는 순간 입출력 예라는 채점 장치가 무너진다** — 같은 입력에 같은 출력이 나오지 않으니, 답을 값으로 정할 수가 없다.
>
> 그 빈자리를 무엇이 메우는가. 시험지의 마지막 두 쪽, 7번과 8번이 답이다. 두 문항에는 문제 설명이 한 줄뿐이고 — *"다음 순서도와 같이 동작하는 코드를 작성하세요"* — 나머지는 전부 그림이다. **답을 값이 아니라 구조로 정한다.** 이 시험지에서 순서도는 장식이 아니라 명세다.

## 여덟 문항이 앞의 스물한 문제와 다른 점

![23-2 중간고사 1쪽 — 1번부터 6번까지](../assets/ch04-p01-중간고사-1번-6번.png)

| 문항 | 무엇을 요구하나 | 값을 돌려주나 | 난수 | 명세가 어디 있나 |
| --- | --- | --- | --- | --- |
| 1 | 첫 글자와 마지막 글자가 같은 문자열 세기 | `print` | — | 예시 출력 한 줄 |
| 2 | 두 리스트에 공통 항목이 있으면 True | **반환한다** | — | 예시 출력 한 줄 |
| 3 | 로또 번호 6개, 중복 금지 | `print` | **`randint`** | 예시 출력 한 줄 |
| 4 | 규칙을 갖는 수식 계산 | `print` | — | **수식 그림뿐** |
| 5 | 복권 당첨 판정 | `print` | **난수** | 실행 예 두 벌 |
| 6 | 주사위 3회 합산, 예외 규칙 둘 | `print` | (주사위) | 예시 두 줄 |
| 7 | 배송비 계산 | `print` | — | **순서도** |
| 8 | 1~1000 숫자 맞히기 | `print` | **`randint`** | **순서도** |

여덟 문항 중 값을 돌려주는 것은 2번 하나뿐이고, 그 2번조차 `(반복문을 활용하세요.)`라는 괄호가 붙어 **파이썬다운 풀이를 금지한다**.

```python
# 교수가 막은 길
def has_common(list1, list2):
    return bool(set(list1) & set(list2))

# 문제가 요구한 길
def has_common(list1, list2):
    for a in list1:
        for b in list2:
            if a == b:
                return True
    return False
```

원본 예시는 `list1 = [1,2,3,4,5,6]`, `list2 = [6,7,8,9,10]` → `True`다. 공통 항목은 6 하나다. 이 괄호 한 쌍이 시험지 전체의 태도를 요약한다 — **답을 구하는 것이 아니라 절차를 적는 것이 시험 대상이다.**

3번도 같은 방식으로 길을 막는다. `1에서 45까지의 난수는 random.randint(1, 45)로 만들면 됩니다`라는 힌트가 `random.sample(range(1,46), 6)`을 봉인한다. `randint`만 남으면 중복을 스스로 처리해야 한다.

```python
import random
nums = []
while len(nums) < 6:
    n = random.randint(1, 45)
    if n not in nums:          # 중복이면 버리고 다시 뽑는다
        nums.append(n)
print(nums)
```

원본 예시 출력 `[1, 42, 37, 22, 14, 20]`은 정렬되어 있지 않다. 뽑은 순서를 그대로 보인다는 뜻이므로 `sorted`를 붙이면 오히려 예시와 달라진다.

## 4번 — 이름이 지워진 원주율

시험지에서 유일하게 문장이 없는 문항이다. `다음의 규칙을 갖는 수식을 계산하는 코드를 작성하세요.` 한 줄 아래에 수식 그림만 있다.

$$3 + \frac{4}{2 \times 3 \times 4} - \frac{4}{4 \times 5 \times 6} + \frac{4}{6 \times 7 \times 8} - \frac{4}{8 \times 9 \times 10} + \cdots$$

규칙 세 가지를 읽어 내야 한다.

1. 분자는 언제나 **4**
2. 분모는 **연속한 세 정수의 곱**이고, 첫 수가 $2, 4, 6, 8, \dots$ 로 2씩 커진다
3. 부호가 `+`, `−`로 **번갈아** 붙는다

$k$번째 항($k = 1, 2, 3, \dots$)의 분모 첫 수는 $2k$이므로 일반항은 이렇게 쓸 수 있다.

$$3 + \sum_{k=1}^{\infty} \frac{(-1)^{k+1} \cdot 4}{2k(2k+1)(2k+2)}$$

이 급수는 이름이 있다. **니라칸타 급수**이고, 수렴값은 $\pi$다. 15세기 인도의 니라칸타 소마야지가 남긴 것으로, 라이프니츠 급수($4 - 4/3 + 4/5 - \cdots$)보다 훨씬 빨리 수렴한다. 시험지에는 그 이름도, 수렴값이 $\pi$라는 사실도 적혀 있지 않다.

```python
total, sign, k = 3.0, 1, 2
for _ in range(100):
    total += sign * 4 / (k * (k + 1) * (k + 2))
    sign = -sign
    k += 2
print(total)          # 3.141592653589793
```

## 5·6번 — 예제가 규칙을 정한다

두 문항 모두 규칙을 한국어로 적어 놓고, 그 한국어가 애매한 자리를 예제가 메운다.

### 5번 — '일치'가 무슨 뜻인가

> 1부터 99까지 2자리의 정수로 이루어진 복권이 있다. 2자리가 전부 당첨 번호와 일치하면 '1등상'이고, **2자리 중 하나만 일치**하면 '2등상'이다.

"하나만 일치"가 두 가지로 읽힌다.

- **자리별 일치** — 십의 자리끼리, 일의 자리끼리 비교한다
- **숫자 포함** — 두 숫자 중 하나가 상대에 들어 있으면 된다

원본이 붙인 실행 예 두 벌이 이 애매함을 정확히 갈라 준다.

| 입력 | 당첨 번호 | 원본이 적은 결과 | 자리별 일치라면 | 숫자 포함이라면 |
| --- | --- | --- | --- | --- |
| 28 | 83 | **미당첨** | 미당첨 (2≠8, 8≠3) | **2등상** (8이 양쪽에 있다) |
| 32 | 33 | **2등상** | 2등상 (십의 자리 3이 같다) | 2등상 |

첫 줄이 결정적이다. 28과 83은 숫자 8을 공유하는데 원본은 **미당첨**이라 적었다. 그러므로 이 문제의 '일치'는 **자리별**이다. 예제 한 줄이 문장 두 줄보다 많은 것을 정했다.

```python
import random
n = int(input('복권 번호(1-99)를 입력하시오: '))
win = random.randint(1, 99)
print(f'당첨 번호는 {win}입니다.')

hit = (n // 10 == win // 10) + (n % 10 == win % 10)
print('1등상' if hit == 2 else '2등상' if hit == 1 else '미당첨')
```

> [!warning] 1~99인데 "2자리의 정수"라 부른다
> 범위를 `1부터 99까지`로 잡아 놓고 `2자리의 정수로 이루어진`이라 적었다. 1~9는 한 자리다. 위 코드처럼 `// 10`으로 십의 자리를 뽑으면 한 자리 수는 십의 자리가 0이 되어, 예컨대 7과 4가 `십의 자리 0끼리 일치`로 2등상이 된다. 이것이 의도인지 아닌지 시험지는 말하지 않는다. 범위가 `10부터 99까지`였다면 생기지 않았을 문제다.

### 6번 — 세 번째 굴림에는 다음이 없다

> 주사위를 3번 굴려서 나오는 점수를 모두 합하여 출력하면 됩니다. 이 때, **1이 나오면 다음 숫자는 합계에서 제외**합니다. […] 반면 **6이 나오면 다음 숫자를 2배로** 더합니다.

원본 예시는 두 줄이다.

- `1, 2, 3 → 4` — 첫 굴림 1은 그대로 더하고(1), 다음 2를 제외하고(0), 3을 더한다. $1 + 0 + 3 = 4$
- `6, 3, 2 → 14` — 6을 더하고(6), 다음 3을 두 배로(6), 2를 그대로. $6 + 6 + 2 = 14$

여기까지는 명확한데, 세 굴림 중 **마지막이 1이나 6이면 "다음 숫자"가 없다.** `1, 2, 6`이면 6은 그냥 더하는가? 원본에 답이 없다. 예시 두 줄이 모두 마지막 자리에 규칙 숫자를 두지 않았기 때문에 이 경우가 드러나지 않는다.

더 곤란한 조합도 있다. `1, 6, 3`이면 6이 "제외" 대상인데, 제외된 6이 그 다음 3에 "2배" 규칙을 거는가? 두 규칙이 충돌하고 시험지는 어느 쪽도 정하지 않았다.

이런 미정 사항이 남는 이유는 이 문항이 **함수가 아니라 프로그램**이기 때문이다. 함수였다면 입출력 예 표를 채우다가 빈칸을 발견했을 것이다. 화면에 찍는 프로그램은 예시 두 줄만 보이면 끝난 것처럼 보인다.

## 8번 — 아홉 번으로는 1000을 감당할 수 없다

![중간고사 8번 — 숫자 맞히기 순서도 (3쪽)](../assets/ch04-p03-중간고사-8번-숫자맞추기-순서도.png)

순서도의 흐름은 이렇다.


`guess = 0`이 초기값인 이유가 여기서 드러난다. 정답은 1 이상이므로 0은 **절대 정답일 수 없는 값**이고, 그래서 첫 `guess != answer?` 검사가 반드시 True가 되어 루프 안으로 들어간다. 입력을 받기 전에 비교부터 하는 구조를 성립시키는 장치다.

```python
import random

tries = 0
guess = 0
answer = random.randint(1, 1000)
print('1부터 1000 사이의 숫자를 맞추시오')

while guess != answer:
    guess = int(input('숫자를 입력하시오: '))
    tries = tries + 1
    if guess < answer:
        print('너무 낮음!')
    elif guess > answer:
        print('너무 높음!')
    if tries > 8:
        break

if guess == answer:
    print('정답입니다')
else:
    print(f'정답은 {answer} 입니다.')
```

`tries > 8`에서 빠져나오므로 **입력 기회는 최대 9번**이다. 그런데 정답은 1000가지다.

한 번 추측할 때마다 얻는 정보는 세 가지다 — 낮다 / 높다 / 맞다. "맞다"가 나오면 그 자리에서 끝나므로, $k$번의 추측으로 확실히 가려낼 수 있는 후보의 최대 개수는 $2^k - 1$이다. 계산하면 이렇다.

| 허용 추측 횟수 $k$ | 확실히 가려낼 수 있는 최대 후보 수 $2^k-1$ | 1000을 감당하나 |
| --- | --- | --- |
| 7 | 127 | 아니오 |
| 8 | 255 | 아니오 |
| **9** (이 순서도) | **511** | **아니오** |
| 10 | 1023 | 예 |

범위 $1 \sim n$을 최악의 경우에도 반드시 맞히려면 몇 번이 필요한지 직접 동적 계획법으로 계산해 확인했다.

| 범위 | 최악의 경우 필요한 추측 횟수 |
| --- | --- |
| 1 ~ 100 | 7 |
| 1 ~ 255 | 8 |
| 1 ~ 511 | 9 |
| 1 ~ 512 | 10 |
| **1 ~ 1000** | **10** |
| 1 ~ 1024 | 11 |

> [!caution] 완벽한 전략으로도 질 수 있는 게임이다
> 이 순서도가 정한 두 값 — 범위 `1 ~ 1000`과 상한 `tries > 8` — 은 함께 성립할 수 없다. 어떤 전략을 쓰든 아홉 번으로는 **최대 511가지**만 가려낼 수 있는데 후보가 1000가지다. 즉 매번 완벽하게 절반으로 쪼개는 사람도 어떤 정답 앞에서는 아홉 번을 다 쓰고 `정답은 [answer] 입니다.`를 보게 된다.
>
> 상한을 `tries > 9`로 한 칸 올리거나 범위를 `1 ~ 500`으로 낮추면 해결된다. 실수인지 의도인지는 시험지가 말하지 않지만, 학생이 코드를 옮겨 적는 데는 영향이 없다 — **순서도를 그대로 옮기는 것이 정답**이고, 이 어긋남은 옮겨 적은 뒤에야 보인다.

## 정리 — 이 시험지에서 가져갈 것

> [!tip] 세 문장 요약
>
> 1. **함수에서 프로그램으로 넘어오면 명세가 흔들린다.** 스물한 개의 연습문제는 입출력 예 표가 답을 못 박았지만, `input`·`print`·`random`으로 이루어진 여덟 문항에서는 그 표가 성립하지 않는다. 그 결과가 4번의 없는 종료 조건, 5번의 애매한 '일치', 6번의 미정 규칙이다.
> 2. **순서도가 그 빈자리를 메운다.** 7·8번은 답을 값이 아니라 **구조**로 정한다. 옮겨 적을 때 조심할 곳은 세 군데다 — 분기마다 좌우가 다른 True/False 라벨, 파이썬 문법이 아닌 `[변수]` 출력 표기, 그리고 순서도에 없는 입력 검증.
> 3. **명세는 옮겨 적은 뒤에야 검증된다.** 8번 순서도는 문법적으로 완벽하고 그대로 옮기면 돌아가지만, 범위 1~1000과 상한 9회가 함께 성립하지 못한다. 코드로 옮기는 일과 명세가 말이 되는지 따지는 일은 별개이며, 이 시험지는 두 번째를 학생에게 맡긴다.

### 근거 자료

이 문서는 강의 원본 `23-2 중간고사.pdf`(3쪽)에 근거한다. 인용한 슬라이드는 1쪽(1~6번), 2쪽(7번 배송비 순서도), 3쪽(8번 숫자 맞히기 순서도)이다. 2·3쪽은 추출 텍스트가 각각 23자뿐인 **이미지 페이지**여서 슬라이드를 직접 보고 순서도의 상자·마름모·화살표·분기 라벨을 하나씩 옮겨 적었다. 본문의 두 mermaid 도해는 원본 순서도의 구조를 그대로 옮긴 것이며 상자 안의 문구도 원문 그대로다.

인터랙티브에 쓴 수치는 계산해 확인했다 — 니라칸타 급수의 부분합(1항 3.1666666667 … 1000항 3.1415926533)과 $\pi$와의 차, 추측 횟수 $k$로 가려낼 수 있는 후보 수 $2^k-1$, 그리고 범위별 최악 추측 횟수(1~100은 7회, 1~511은 9회, 1~1000은 10회, 1~1024는 11회)는 동적 계획법으로 직접 구한 값이다.

원본에 없는 보충은 세 가지이며 본문에 그 사실을 밝혔다 — 4번 수식이 니라칸타 급수이고 $\pi$로 수렴한다는 사실(원본은 이름도 수렴값도 적지 않았다), 8번의 범위와 상한이 양립하지 않는다는 분석, 그리고 각 문항의 파이썬 구현이다. 5번의 '일치'를 자리별 비교로 확정한 근거는 원본 실행 예 `28 / 83 → 미당첨` 한 줄이다.
